## Professional Self-Assessment

Throughout the Computer Science program at Southern New Hampshire University, I have developed a broad and increasingly specialized set of skills that have prepared me to enter the professional world of computer science with a clear sense of purpose and direction. My goal is to build a career in cybersecurity and data security, and the work completed across this program, culminating in the ePortfolio developed in CS 499, reflects a consistent commitment to that path. Earning the CompTIA Security+ certification during this time further strengthened my technical foundation and demonstrated a baseline level of competency in security concepts that employers in this field recognize and value. Prior to and during this program, I worked for the Social Security Administration, an experience that gave me firsthand exposure to the kind of data that is most sensitive and most consequential when it is not properly protected. Working with personal, financial, and medical data across multiple platforms made it clear very early that data security is not a theoretical concern but an immediate and ongoing responsibility. That experience shaped how I approach every technical decision, and it is the lens through which the work in this ePortfolio was built.

The centerpiece of this ePortfolio is the Inventory App, an Android mobile application originally developed in Java using Android Studio as the final project for CS 360: Mobile Architecture and Programming. Across three enhancement categories in CS 499, this single artifact was systematically analyzed, critiqued, and improved to demonstrate growth in software design and engineering, algorithms and data structures, and databases. This approach reflects the kind of iterative, improvement-driven development cycle that is standard in professional software environments, where code is never simply written and left alone but continuously reviewed and refined. The code review completed early in the course simulated the collaborative peer review process foundational to professional development teams, producing a structured walkthrough of the existing code, its weaknesses, and a clear plan for improvement. Communicating those findings in a way that both technical and non-technical stakeholders could understand and act on was just as important as the technical analysis itself, and preparing that review reinforced how much effective collaboration depends on clear, organized communication. The sections that follow present the code review, the three enhanced versions of the artifact, and the narratives that document the skills demonstrated and the reasoning behind each improvement.

Software design and engineering is about more than making code work. It is about making code that can be understood, maintained, and extended by anyone who encounters it. Throughout this program, I developed the ability to evaluate existing code critically, identify structural weaknesses, and apply software design principles to produce cleaner and more reliable solutions. Courses focused on computer networking, which I found particularly engaging, also reinforced how interconnected modern systems are and how design decisions at any layer of a system can have security implications at every other layer. Algorithms and data structures gave me the foundation to think carefully about how data is organized and accessed, and how those choices affect the performance and usability of the software that users actually interact with. Understanding the trade-offs involved in different approaches is a skill that applies to every technical decision made in a professional environment.

Database security is the area where my professional background and academic training come together most directly. Knowing that real people's most sensitive information lives inside database tables makes abstract security concepts immediately concrete. The program gave me the technical vocabulary and skills to address those vulnerabilities directly, from understanding how credentials should be stored to recognizing how input handling can become an attack surface if not carefully designed. Security is not a feature that can be added after the fact. It has to be built into the foundation of a system from the start, and that mindset is something I carry into every technical decision.

My time at the Social Security Administration made the stakes of data security very real. There is an enormous amount of personal data in the world today, much of it more accessible than it should be, and the people whose data is exposed rarely have any say in how it was protected. The most effective mitigation is not reactive but preventive, designing systems that anticipate how they might be attacked and building those protections in from the start. The artifacts in this ePortfolio demonstrate that philosophy in practice. They are not perfect systems, but more secure, more maintainable, and more usable ones than where they started, built by someone who understands why that work matters.
